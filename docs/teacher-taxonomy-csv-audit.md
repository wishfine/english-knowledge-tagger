# 教师知识点释义 CSV 审计

## 1. 审计对象与结论边界

审计对象：

`data/rulebooks/初中英语知识点题型方法释义.csv`

本次只审 `知识点->...` 的 386 条记录；`题型->...` 的 190 条记录不纳入本报告。审计检查知识点定义、可适用题型边界、示例和元数据，不把历史数据中的标签频次当成真值，也不直接修改源 CSV。结论分成三类：

1. **字段或内容损坏**：应先修复，否则会污染后续 prompt 和规则。
2. **定义存在歧义/边界不足**：需要形成 versioned policy overlay，并用抽样实验验证，不能直接全量替换。
3. **定义本身未必错误，但缺少路由或示例**：属于可执行性风险，需补充元数据。

## 3. P0：必须先处理的结构性问题

### 3.1 “问题”列有 12 条疑似列错位

列 `原始释义是否有理解问题/压缩后的释义是否依然存在问题` 按约定应填写 `否`，但以下 12 行填入了一整段释义文本。它们看起来像是把原始定义误写进了问题标记列：

| CSV 行 | 标签 |
|---:|---|
| 139 | `知识点->词法->非谓语动词->动词不定式->动词不定式的结构->动词不定式的一般式` |
| 156 | `知识点->词法->非谓语动词->分词->现在分词` |
| 196 | `知识点->词法->主谓一致->语法一致` |
| 204 | `知识点->句法->句子成分->补语` |
| 210 | `知识点->句法->句子种类->疑问句->特殊疑问句->how类特殊疑问词` |
| 211 | `知识点->句法->句子种类->疑问句->特殊疑问句->wh-类特殊疑问词` |
| 213 | `知识点->句法->句子种类->疑问句->反意疑问句` |
| 276 | `知识点->语篇体裁->记叙文` |
| 277 | `知识点->语篇体裁->说明文` |
| 278 | `知识点->语篇体裁->议论文` |
| 279 | `知识点->语篇体裁->应用文` |
| 282 | `知识点->语篇体裁->新媒体语篇` |

处理建议：

- 先逐行对照原始释义列和压缩释义列，确认文本没有丢失；
- 将问题列恢复为 `否` 或明确的人工结论；
- 在修复前，任何程序都不能用这个列筛选“问题标签”；
- 修复应作为 CSV 的新版本或独立 patch，保留原始文件哈希。

### 3.2 表头末尾有 32 个空列

CSV 物理表头共有 41 列，但只有前 9 列有列名；最后 32 列列名为空，且 576 条数据行对应位置也全部为空。它目前没有改变前 9 列的内容，但会带来两个风险：

- 不同 CSV 解析器对重复空列名的处理不同，可能覆盖字段或生成难以追踪的列名；
- 后续导出、拼接或转 JSON 时容易把这些空列误当成真实字段。

建议在保留原始哈希的前提下生成一个规范化 CSV：只保留前 9 个有意义的列，并在 manifest 中记录“删除 32 个全空列”。这属于格式清理，不应改变任何标签文本。

## 4. P1：定义本身有明显歧义或容易过标

### 4.1 词汇音/形/义的五个标签过宽

以下 5 个标签都写了“所有涉及到写……都打此类标签”：

- `知识点->词汇->词汇（音/形/义）->名词（短语）的音/形/义`
- `知识点->词汇->词汇（音/形/义）->动词（短语）的音/形/义`
- `知识点->词汇->词汇（音/形/义）->形容词（短语）的音/形/义`
- `知识点->词汇->词汇（音/形/义）->副词（短语）的音/形/义`
- `知识点->词汇->词汇（音/形/义）->介词（短语）的音/形/义`

问题不在于“写单词”这个现象，而在于该规则会把所有含有名词/动词等答案的填空题都打上音形义标签，即使解题真正依赖的是时态、语态、非谓语、构词法或固定搭配。

建议改成：**只有当答案的拼写、读音或词义本身是作答所需判断时才标；若词形由时态/语态/构词规则决定，则以相应语法/构词标签为主，必要时再并行标音形义。**

### 4.2 固定搭配/句型标签缺少“直接依赖”门槛

`知识点->词汇->固定搭配/句型` 写了“只要题干涉及到固定搭配/固定句型，都需要打上此标签”。这会把搭配仅作为背景信息、而答案实际由其他规则决定的题目也纳入。

建议加门槛：答案必须直接依赖该固定搭配/句型的槽位、连接词、动词形式或含义匹配；仅在解析中顺带出现的搭配不标。

### 4.3 构词法：转化法与派生法的边界和示例有问题

`知识点->词汇->构词法->转化法` 的 `like→likes` 示例是屈折变化，不是转化法。转化法应强调“词形不变、词性/词义功能改变”，如 `water (n.) -> water (v.)`；添加 `-or/-ness/-tion` 等词缀应归派生法。

此外，`合成法` 的注意事项仍写成“转化后的单词拼写”，与转化法重复，疑似复制错误，应改为“合成后的单词拼写”或泛化为“构词后的单词拼写”。

这是当前转化法实验中反复出现边界误判的直接来源，必须先在策略层修订，再扩大 DS 全量实验。

### 4.4 语法结构标签常把“出现”误当成“考查依赖”

`主语`、`谓语`、`宾语`、`补语`、`状语`、`定语` 等定义多以“句中有该成分”为触发条件，但题目出现某成分不等于答案由该成分决定。特别是：

- `补语` 容易把主语补语/表语与宾语补语混在一起；
- `how类特殊疑问词`、`wh-类特殊疑问词` 与时间、频率、数量、距离等语用标签重叠；
- 时态的“定义/判定”“肯否疑”“形式变化”边界不总是清楚；
- 不定式、分词、动名词的词形和句法功能需要分开，否则会把“出现 -ing”直接判成同一标签。

建议所有结构标签统一加一句：**只有当选择/填写答案必须依赖该结构或成分的判定时才标；单纯出现在题干中不触发。**

### 4.5 语用“时间”三类标签重叠明显

`知识点->语用->时间->时刻`、`时段`、`频率`、`顺序` 的关键词大量交叉：`When`、`What time`、`How long`、`How soon`、`before/after`、日期和星期等都可能同时出现。

其中 `时间->顺序` 的定义尤其宽，把以下内容混在一起：步骤顺序、事件先后、星期/日期顺序、历史事件顺序、时间状语和时态。当前 Order-1 实验已经观察到它会吸收普通日期、`How soon/How long` 和其他时间题。

建议拆成互斥的作答依赖：

- `时刻`：答案必须是具体钟点/钟表读数；
- `时段`：答案必须是持续时长或时间段，且区分 `How long` 与 `How soon`；
- `频率`：答案必须表达重复频率/次数；
- `顺序`：答案必须依赖两个或多个事件、步骤或时间点之间的相对先后关系；只问一个日期、钟点或持续时长不标。

### 4.6 社会交往标签是高重叠的语用簇

`介绍`、`问候`、`致谢`、`邀请`、`请求允许`、`劝告/建议`、`询问`、`描述`、`决定`、`意图` 等标签大量共享 `Can/Could/Would/should/Let's` 和常见问句形式。

单纯依赖关键词会产生系统性误标。例如 `询问`/`描述` 可能吸收几乎所有 WH 问句，`请求允许`/`请求帮助`/`建议` 可能互相覆盖。

建议用“言语行为 + 答案直接完成的交际功能”判定，而不是关键词命中；同时为每个标签补充反例和相邻标签排除项。

### 4.7 语篇主题和体裁定义粒度不一致

37 个 `语篇主题` 标签多数只有一行关键词，且允许“除了单选、语音题外的所有题型”。这会让主题词只作为背景出现时也触发标签；`互联通讯` 等主题已在实验中表现出明显波动。

`记叙文`、`说明文`、`议论文`、`应用文`、`新媒体语篇` 之间也缺少统一的体裁判据，存在主题/体裁混淆。

建议分别定义：

- 主题：文章/对话的主要内容必须围绕该主题，而非偶然提及；
- 体裁：由篇章组织、交际目的和格式决定，不由主题词决定；
- 阅读小题是否打主题/体裁，应按表格规定和题目层级单独处理，不能从父题机械继承。

## 5. P1/P2：不是定义错误，但不足以支持稳定自动化

### 5.1 52 条知识点没有标准化题型路由

按审计规则，以下类别没有形成统一的“适用题型/排除题型”结构（有些文本里含自然语言范围，但不能直接被路由程序可靠解析）：

- 37 个 `知识点->语篇主题->...` 叶子；
- 11 个 `知识点->词汇->词汇（音/形/义）` 与 `词汇辨析` 叶子；
- `知识点->词法->动词时态->其他时态`；
- `知识点->语篇体裁->其他语篇`；
- `知识点->语用->情景交际用语（综合）`；
- `知识点->其他`。

这不意味着 52 个标签全部错误，而是它们不能直接进入“按题型缩小候选池”的自动规则。需要补 `include_routes`、`exclude_routes`、`scope` 和 `fallback` 属性。

### 5.2 “无明确说明”不是可执行的负规则

压缩释义中出现 `无明确说明` 的知识点有 59 条。它表示当前定义没有明确的排除边界，尤其集中在：

- 代词/介词/非谓语/时态/主谓一致；
- 句子成分和特殊疑问句；
- 社会交往、态度、情感；
- 时间类语用；
- 语篇体裁。

这些标签不能仅凭正向关键词进入高质量集，至少要经过独立抽检或补充反例。

### 5.3 “新题不打”知识点必须隔离

以下 2 个知识点标签明确写了“新题不打”：

- `知识点->语用->情景交际用语（综合）`
- `知识点->其他`

它们可以保留用于历史审计和回溯，但不能作为新数据的正常候选，也不能因为缺少更具体标签就自动回填。

### 5.4 兜底标签要有证据门槛

含“其他/其它/综合”的标签不一定错误，但容易成为模型无法判断时的默认出口，例如：

- `知识点->词法->动词->系动词->其他系动词`
- `知识点->词法->动词时态->其他时态`
- `知识点->语篇体裁->其他语篇`
- `知识点->语用->情景交际用语（综合）`
- `知识点->其他`

策略上应规定：只有已排除所有具体兄弟标签、且题目证据明确属于该兜底范围时才允许使用；“模型不确定”应输出 hold/insufficient，而不是兜底标签。

## 6. 多标签支持是当前 CSV 的主要缺口

CSV 中 377/386 条知识点记录的 `所含其他知识点（除当前知识点外）` 为空，372/386 条知识点记录没有多知识点题干。其余少量记录中还有 `/` 这类占位符，不能视为完整共现图。结果是：

- 无法从 CSV 得到同题并行标签的先验关系；
- 无法判断哪些标签可共现、哪些标签应互斥；
- 容易把一个题的所有现象都塞给当前正在处理的标签，或反过来漏掉并行标签；
- 现有“逐标签处理、最后按 `question_id` 合并”的流程缺少规范化的共现约束。

建议新增独立的 policy overlay（不要先覆盖源 CSV），至少为每个标签保存：

```json
{
  "label": "知识点->...",
  "scope": ["parent", "child"],
  "include_routes": [],
  "exclude_routes": [],
  "positive_dependency": "答案必须直接依赖的判据",
  "allowed_co_labels": [],
  "mutually_exclusive_labels": [],
  "fallback": false,
  "counterexamples": [],
  "policy_version": "..."
}
```

这样可以继续逐标签跑 DS，但最终以 `question_id` 合并所有通过验证的标签；一次只处理当前标签，不强迫 DS 在一次调用中穷举全树。

## 7. 建议处理优先级

### P0：先修数据和规则基础

1. 修复 12 条知识点“问题列”错位。
2. 固化知识点候选只使用 `知识点->...` 前缀，隔离 2 个“新题不打”知识点和兜底标签。
3. 修订转化法/派生法/合成法定义，删除 `like→likes` 这类屈折变化示例。
4. 为五个音形义标签、固定搭配标签增加“答案直接依赖”条件。

### P1：优先验证高风险定义簇

1. 词汇音形义与词汇辨析；
2. 构词法（转化法、派生法、合成法）；
3. 语用时间（时刻、时段、频率、顺序）；
4. 社会交往/态度/情感语用；
5. 语篇主题与体裁；
6. 主谓一致、时态、非谓语、句子成分等结构标签。

每个标签先做小批量：历史标签 + DS 候选 + 网页 GPT/Gemini 复核；冲突或证据不足统一进入 hold，不直接改真值。通过后再做全量。

### P2：补齐可执行元数据

逐标签补充 3 类示例：

- 正例：为什么必须打该标签；
- 邻近反例：看起来相似但不应打的题；
- 共现例：同题还应并行打哪些标签。

优先补 307 个缺少常见题干、以及所有主题/语用/词汇辨析标签。没有反例的标签，不应仅凭关键词自动放行。

## 8. 对后续知识点 pipeline 的直接影响

- 当前 CSV 可以继续作为教师知识树的来源，但不能直接视为“已经可执行的金标准”。
- 知识点候选必须只从 `知识点->...` 前缀生成；题型字段由另一份题型审计负责，不在本报告中混用。
- 题型路由应先按 `scope × 题型结构 × 题型名称` 约束知识点候选，再按知识点 policy overlay 过滤；没有明确路由的标签先进入人工配置队列。
- 多标签题采用“逐标签判定、按 `question_id` 合并”的策略；当前标签只决定当前标签是否成立，不负责替其他标签下结论。
- DS 输出应保留 `decision`、`confidence`、`evidence` 和 `status`；`insufficient/unparsed` 不能强行映射为任一标签。
- CSV 的原始释义、压缩释义、问题列和策略 overlay 要分别版本化，避免后续无法判断某次实验使用了哪一版定义。

## 9. 一句话结论

这份 CSV 的**386 个知识点目录本身完整且无重复**，但还不是可以直接驱动全量自动标注的金标准：最紧急的是 12 条知识点字段污染、知识点候选与题型分池，以及转化法、音形义、固定搭配、时间语用和社会交往等定义的边界不足。后续应先修 P0，再按标签建立可执行 policy 和反例，逐个实验放大。
