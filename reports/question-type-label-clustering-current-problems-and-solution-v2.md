# 题型标签聚类现有问题与解决方案

_版本：V2；更新时间：2026-09-02；范围：完整大题的逐标签局部聚类及后续全局归并_

---

## 📋 技术摘要

当前路线应继续采用“逐旧标签局部聚类，再做跨标签全局合并”。旧标签只负责分批，不能作为最终题型边界；聚类对象只包含 `is_sub_question=false` 的完整大题，不处理小题题型。

实验已经确认两个结论：

- 直接对题目逐条聚类会因 `task_mechanism` 的自然语言差异产生严重碎片化
- 先按标准化后的 `candidate_type_label` 分组，能够彻底避免同名题型被拆散，但仅靠名称和机制各占一半仍无法充分合并跨名称的同类题型

V3 已将三个标签的簇数从逐题机制主导版本的 `337 / 161 / 306` 降至 `25 / 11 / 56`，说明“候选名称组作为最小聚类单位”是正确方向。但是，“听力图片匹配”“听句子选图”和“听力匹配题”等相同大题型仍保持为独立簇，说明当前结果是**高精度、低召回**：已经合并的名称通常合理，但应合并的近义名称仍然较多。

现行 V4 方案不增加 DS 调用、语义嵌入、关键词特征或新字段。它保留 V3 的名称组结构，将组间比较调整为机制主导，并修复组中心向量长度不一致造成的实际权重漂移：

```text
candidate_type_label = 0.2
task_mechanism       = 0.8
```

V4 已完成代码实现，仍需使用同一批三标签数据重跑并验证合并结果。本报告中的 V3 数字是已观察结果；V4 部分是当前解决方案及验收标准，不是尚未发生的实验结论。

## 🎯 范围、目标与判断口径

### 处理范围

- 原始数据：`cleaned_final_enhanced_v2.jsonl`
- 只处理：`is_sub_question=false`
- 不处理：`is_sub_question=true`
- 局部处理单位：一个旧题型标签下的全部已打标大题
- 当前试验单位：三个典型旧标签，每个标签1000题

三个典型标签为：

1. `题型@特殊题型@语法填空@语法填空（动词）`
2. `题型@完形填空@词性@完形：动词/动词短语`
3. `题型@听力理解@听力匹配`

### 目标粒度

当前任务只判断完整大题属于什么题型，不再保留完形填空单个空的词性、阅读单个设问功能等小题粒度。

在这一口径下，“听力图片匹配”“人物信息匹配”“听句子选图”等材料或对象差异，不需要自动形成不同的大题型；只要核心作答机制是听取材料并完成匹配，就可以归入“听力匹配”。

### 成功标准

局部聚类需要同时满足：

- 同一个标准化候选名称永远不被拆分
- 不同名称但大题机制相同的名称组能够合并
- 单项选择与完形填空等实质不同机制仍保持分离
- 原标签中的真实混标仍能被发现
- 每道题只进入一个局部簇或异常记录，不重复、不丢失

## 📊 三轮试验揭示了问题边界

### 方法演进对比

| 版本 | 最小聚类单位 | 名称/机制权重 | 语法填空簇数 | 完形标签簇数 | 听力匹配簇数 | 主要表现 |
| --- | --- | ---: | ---: | ---: | ---: | --- |
| V1 | 单题 | `0.7 / 0.3` | 21 | 9 | 46 | 名称主导，簇数较少但同名仍可能被拆分 |
| V2 | 单题 | `0.3 / 0.7` | 337 | 161 | 306 | 机制表述差异被放大，出现严重碎片化 |
| V3 | 候选名称组 | `0.5 / 0.5` | 25 | 11 | 56 | 同名不再拆分，但跨名称归并不足 |
| V4 | 候选名称组 | `0.2 / 0.8` | 待运行 | 待运行 | 待运行 | 机制主导，并统一组特征块尺度 |

簇数只能用于观察碎片化程度，不能单独代表聚类质量。V1 的簇数比 V3 少，并不证明 V1 更准确；还必须检查同机制是否合并、不同机制是否误合并，以及单例簇是否合理。

### V3 已验证结果

| 旧标签 | 候选名称组 | 最终簇 | 名称组压缩率 | 稳定簇覆盖题数 | 单例簇 | 异常题 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 语法填空（动词） | 31 | 25 | 19.4% | 976 | 10 | 2 |
| 完形：动词/动词短语 | 13 | 11 | 15.4% | 983 | 3 | 1 |
| 听力匹配 | 74 | 56 | 24.3% | 935 | 30 | 3 |

每个标签均有1000题。三组数据都满足：

```text
聚类成员数 + 异常题数 = 1000
```

聚类成员中的题目键保持唯一，没有发现重复或遗漏。

### V3 已经正确完成的合并

V3 对表面近义名称的合并总体可靠，例如：

- `单词拼写 / 单词拼写填空 / 单词拼写题`
- `单句首字母填空 / 首字母填空`
- `听力图片匹配 / 听力图片匹配题 / 图片匹配题`
- `听句子选图 / 听句子选图片 / 听句子选图画`
- `听对话选图 / 听对话选图片`

目前未观察到这些大规模合并中存在明显的错误归并。因此，当前问题不是合并过度，而是跨表述合并不足。

### 听力匹配仍被明显过度拆分

| 题数 | V3 局部候选名称 |
| ---: | --- |
| 262 | 听力图片匹配、听力图片匹配题、图片匹配题 |
| 258 | 听句子选图、听句子选图片、听句子选图画 |
| 216 | 听力匹配题 |
| 58 | 句子与图片匹配等 |
| 55 | 听力配对题 |
| 19 | 听描述选图等 |
| 13 | 听句子选画面 |
| 10 | 听音选图 |

这些簇的机制摘要都接近“听取音频内容，将内容与对应图片或选项进行匹配”。按照当前的大题型粒度，它们应主要归入同一个“听力匹配”局部主簇，而不应因为“图片、句子、画面、描述”等对象差异继续拆分。

### 完形标签暴露了真实混标

`题型@完形填空@词性@完形：动词/动词短语`下主要存在：

- 单项选择：645题
- 完形填空：323题
- 语篇填空：15题

这里不能为了减少簇数而全部合并。“独立句子中选择答案”和“共享语篇中完成多个空”是不同的大题机制。该结果可能来自旧标签混标，也可能来自原题缺少完整上下文导致模型只看到单项选择形式；无论原因如何，都说明旧标签不能直接作为最终题型。

## 🔍 现有问题说明

### 问题一：模型自主命名必然产生近义标签

新版打标路线不提供固定题型树，模型根据题目自主生成 `candidate_type_label`。因此，以下差异是预期现象，不应直接转化为最终题型边界：

- 选图、选择图片、图片匹配
- 配对、匹配、搭配
- 图、图片、图画、画面
- 语法填空、单句语法填空、适当形式填空

聚类的职责正是把这些近义表达归一化，而不是要求模型从一开始只输出唯一标准名称。

### 问题二：逐题机制聚类会把语言差异当成题型差异

`task_mechanism` 是自由文本。同一题型可能因为材料缺失、题面写法、模型措辞和信息详略产生不同描述。V2 将机制权重提高到0.7后，三个标签分别形成337、161和306个簇，说明逐题聚类把这些表述差异放大成了大量小簇。

因此，不能回到“机制权重越高，直接逐题聚类越好”的路线。机制主导必须建立在候选名称组之上。

### 问题三：V3 仍然过度依赖候选名称

V3 的候选名称和机制权重均为0.5。字符级 TF-IDF 主要依靠表面字符重合，“听句子选图”和“听力匹配题”的名称重合有限。即使机制接近，名称部分仍可能把综合相似度拉低，阻止两个名称组合并。

这使 V3 更擅长合并轻微写法变化，却不擅长合并名称不同、机制相同的大题型。

### 问题四：组中心的实际权重会发生漂移

V3 对一个候选名称组内的机制向量求平均。组内机制表述越多样，平均机制向量的长度通常越小；候选名称向量则因为组内名称相同而相对稳定。

如果直接将两个中心乘以0.5后拼接，配置中的 `0.5 / 0.5` 并不等于每个名称组实际具有相同的名称和机制影响。内部表述更丰富的大组可能再次被名称部分主导。

### 问题五：聚类粒度高于当前业务需求

此前分析会考虑图片匹配、人物信息匹配、听句子选图等细分差异，但当前目标只需要完整大题的主要任务机制。继续把材料对象、音频单位或选项形式当成主要边界，会重新引入粒度漂移。

当前应优先回答“它是不是听力匹配”，而不是继续回答“它属于哪一种听力匹配”。

### 问题六：稳定簇和低异常率不等于题型已经归一

V3 的稳定簇覆盖了大部分题目，异常题也只有 `2 / 1 / 3`。这些指标证明数据处理完整、主名称稳定，但不能证明跨名称归并已经完成。

例如听力匹配已有935题位于稳定簇中，却仍存在56个簇和30个单例簇。因此，必须同时查看候选名称组压缩率和主机制是否跨名称合并。

## ⚙️ V4 解决方案保持简单且机制主导

### 只使用现有模型输出

局部聚类继续只使用：

- `candidate_type_label`
- `task_mechanism`
- `confidence`
- `information_sufficiency`
- `status`

不从题干中重新提取 `material_medium`、`primary_operation` 等结构化特征，也不增加一次 DS 判断。

### 继续按候选名称组聚类

处理流程先对候选名称做保守的表面归一化，再把相同标准化名称的题目组成不可拆分的名称组。层次聚类比较的是名称组，而不是单道题。

这项约束保留 V3 已经解决的问题：同一个候选名称不会因为机制文本写法不同而被拆成多个簇。

### 分别归一化两个组中心

每个名称组生成两个中心：

1. 候选名称 TF-IDF 中心
2. 任务机制 TF-IDF 中心

V4 先分别对两个中心做 L2 归一化，再应用配置权重并拼接。这样可以避免组内机制描述越丰富，机制特征反而越弱的问题。

### 将组间比较调整为机制主导

V4 使用：

```text
candidate_label_weight = 0.2
task_mechanism_weight  = 0.8
```

候选名称仍用于避免完全无关机制因通用表达而误合并，但主要判断依据变为已有的 `task_mechanism`。

### 保持原有聚类算法和阈值

本轮不同时修改过多变量：

```text
算法：AgglomerativeClustering
距离：cosine
连接方式：average
local_distance_threshold = 0.48
auxiliary_similarity_threshold = 0.52
```

保留原阈值可以把 V4 的变化主要归因于特征块归一化和权重调整。如果 V4 仍然合并不足，再单独评估距离阈值；不在本轮进行大规模参数搜索。

### 保留质量分层和簇状态

- `core`：状态有效、信息充分或部分充分、置信度不低于0.7
- `auxiliary`：未被排除且置信度不低于0.4，但未达到核心条件
- `excluded`：状态错误、信息不足、必要字段缺失或置信度过低

局部簇继续分为：

- `stable`：至少5题
- `micro`：2至4题
- `unresolved`：1题

辅助名称组只能加入达到相似度阈值的核心簇，否则进入异常记录，避免低置信度结果独立创造新题型。


## 📌 方案边界与不采用的做法

当前阶段明确不采用：

- 对原题重新调用 DS 提取机制特征
- 新增材料媒介、材料单位、作答支架等结构化字段
- 引入外部嵌入模型或向量数据库
- 为每一个旧标签编写独立的大量关键词规则
- 将某个旧标签下的全部题目无条件合并
- 把图片、人物、地点等匹配对象自动视为不同大题型

这些做法要么增加运行成本和系统复杂度，要么会让旧标签重新成为最终边界。当前优先验证能否仅依赖已有候选名称和任务机制完成足够可靠的局部归并。

## ✅ V4 重跑后的验收标准

### 通用检查

每个旧标签必须满足：

```text
clustered_rows + outlier_rows = total_rows
```

同时检查：

- 题目键无重复
- 同一标准化候选名称只属于一个局部簇
- 异常记录有明确原因
- 报告记录 V4 权重和 `l2-before-weighting`

### 听力匹配

预期将以下主簇显著归并：

- 听力图片匹配
- 听句子选图
- 听力匹配题
- 句子与图片匹配
- 听力配对题
- 听描述选图
- 听音选图

验收重点不是要求只剩一个簇，而是这些机制一致的主名称不应继续形成数百题规模的相互独立簇。明显的填空、非听力任务或无法判断数据仍应保持分离或进入异常记录。

### 语法填空

语法填空、单句语法填空、适当形式填空等相同大题机制应进一步合并；单词拼写、首字母填空、完成句子等不同作答机制不应因为都需要填写答案而被全部合并。

### 完形标签

单项选择和完整完形填空两个主要机制应继续保持分离。V4 可以合并各自内部的近义名称，但不能仅因它们来自同一旧标签而合并为一个簇。

### 对比指标

重跑后至少比较：

- 候选名称组数量与最终簇数量
- 实际发生跨名称合并的簇及其名称清单
- 单例簇数量
- 异常题数量及原因
- 三个最大簇的名称组成和机制摘要
- 是否出现明显不同机制的错误合并

只有“同机制合并增加”且“不同机制没有明显误合并”同时成立，才能判断 V4 优于 V3。

## 🔄 局部结果如何进入最终题型体系

V4 仍然只产生局部候选簇，不直接确定最终标准题型。完整路线为：

```text
逐旧标签处理题目
→ 形成局部机制簇
→ 汇总局部簇摘要
→ 跨标签比较、合并和必要拆分
→ 统一近义名称
→ 确定全局标准题型
→ 回写每道题
```

局部阶段保留旧标签上下文，可以降低一次处理全部题目的复杂度；全局阶段只比较局部簇摘要，可以避免重新混合全部题目。最终合并仍以大题任务机制为依据，旧标签不能阻止不同来源下的同机制簇合并。

## 🤔 待验证问题

V4 重跑后需要回答：

1. 机制主导是否能把听力匹配的多个百题级主簇合并？
2. 语法填空中的相近填空机制是否归并，同时保留单词拼写等真实差异？
3. 完形标签中的单项选择和完形填空是否仍保持清晰边界？
4. 组特征分别归一化后，是否出现通用机制文本导致的错误合并？
5. 若仍然合并不足，下一步是否只调整距离阈值，而不增加新特征或模型调用？

上述问题应先通过三个典型标签回答，再决定是否将 V4 扩展到其余全部旧标签。
