# 题型标签聚类现有问题与解决方案

_文档修订：2026-09-02；比较基线：V1；最新版：V4；实验对象：三个典型旧标签各1000题_

---

## 📋 技术结论

最新一版为 V4。它相对 V1 有两项明确改进：提高了可聚类题目的覆盖率，并且能够发现 V1 不会发现的跨名称、跨簇合并关系。例如，语法填空中的“语法填空”和“单句语法填空”由两个 V1 簇合并为875题的大簇；听力匹配中也出现了多个跨 V1 簇的合并。

但 V4 **不能直接替代 V1**。三个标签的簇数均高于 V1：

```text
语法填空：21 → 27
完形标签： 9 → 11
听力匹配：46 → 49
```

成员交叉检查进一步表明，V4 在产生新合并的同时，也拆开了 V1 已有的合理簇：语法填空有3个 V1 簇被拆分，完形标签有2个，听力匹配有9个。因此，当前最合适的使用方式不是接受 V4 的完整分区，而是：

> **保留 V1 簇作为不可拆分的基础单元，只使用 V4 提供跨 V1 簇的合并证据。**

这样能够保留 V1 已有的稳定结果，同时获得 V4 在机制归并方面的新增能力。

V2、V3属于中间调参过程，不作为本报告的主要比较对象。评价最新版是否有效，只比较相同数据上的 V1 与 V4。

## 🎯 实验范围与评价口径

### 数据范围

- 每个旧标签抽样1000题，共3000题
- 只处理 `is_sub_question=false` 的完整大题
- 不处理 `is_sub_question=true` 的小题
- V1和V4使用相同的模型打标结果
- 旧标签只用于分批，不是最终题型边界

三个试验标签为：

1. `题型@特殊题型@语法填空@语法填空（动词）`
2. `题型@完形填空@词性@完形：动词/动词短语`
3. `题型@听力理解@听力匹配`

### 当前题型粒度

当前目标是完整大题的主要任务机制，不再区分完形填空单个空所考查的词性，也不要求把图片匹配、人物信息匹配、听句子选图拆成不同的听力大题型。

例如，只要核心任务是听取音频后完成对应关系匹配，就可以归入“听力匹配”。图片、人物、地点或句子只是匹配对象，不是当前需要保留的题型层级。

### 评价标准

不能只看最终簇数，还需要同时检查：

- 同机制、不同名称的簇是否合并
- V1中已经合理的簇是否被拆开
- 不同任务机制是否发生错误合并
- 异常题是否减少
- 题目是否重复或遗漏

| 旧标签 | V1簇数 | V4簇数 | 簇数变化 | V1聚类题数 | V4聚类题数 | V1异常题 | V4异常题 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 语法填空（动词） | 21 | 27 | +6 | 996 | 998 | 4 | 2 |
| 完形：动词/动词短语 | 9 | 11 | +2 | 999 | 999 | 1 | 1 |
| 听力匹配 | 46 | 49 | +3 | 989 | 997 | 11 | 3 |

数据完整性检查通过：每个版本、每个标签均满足“聚类题数 + 异常题数 = 1000”，聚类成员中的题目键保持唯一。

从总体指标看，V4的主要优势是覆盖率提高：

- 语法填空新增2道可聚类题
- 完形标签覆盖率不变
- 听力匹配新增8道可聚类题，异常题从11道下降到3道

但簇数全部上升，说明 V4 在引入新合并的同时产生了新的拆分，不能把簇数变化直接解释为聚类改善。

## 🔍 三个标签呈现不同的收益与回退

### 语法填空获得一个重要合并，但拆散了其他V1簇

#### V4的有效改进

V1分别保留：

- 语法填空：846题
- 单句语法填空：29题

V4将两者合并为875题的大簇。这是本轮最明确的机制归并改进，因为二者在当前大题型粒度下都属于语法填空。

V4还把可聚类题目从996道提高到998道，异常题从4道降到2道。

#### V4产生的回退

V1中的“单词拼写”相关22题原本位于一个簇中：

```text
单词拼写填空17题 + 单词拼写3题 + 单词拼写题2题 = 22题
```

V4把它拆成：

- 单词拼写填空：17题
- 单词拼写、单词拼写题：5题

V1中的首字母填空10题也被拆成8题主簇和更小的独立部分。成员交叉表显示，共有3个 V1 簇被 V4 拆分，而 V4只有1个簇真正合并了多个 V1 簇。

因此，语法填空的结论是：V4发现了一个重要的新合并，但不应以拆开已有单词拼写、首字母填空簇为代价。

### 完形标签没有获得实质改进

V1和V4都识别出三个主要群体：

- 单项选择：645题
- 完形填空：323题
- 语篇填空：15题

这三个主要边界保持稳定，说明原标签内部确实存在明显的题型混合，或者部分题目缺少完整语篇上下文。无论是哪种情况，“单项选择”和“完整完形填空”都不能因来自同一个旧标签而直接合并。

V4没有形成任何合并多个 V1 簇的新簇，反而拆开了2个 V1 簇：

- V1的6题语法填空簇被拆为3题“语法填空”和3题“语篇型语法填空”
- V1的4题语法选择簇被拆为3题和1题

最终簇数由9个增加至11个，覆盖率和异常题数均未改善。

因此，对完形标签而言，V4当前属于回退，不存在足以抵消拆分问题的新增收益。应直接保留 V1 分区。

### 听力匹配产生了有价值的跨簇连接，但仍未完成主类型归并

#### V4新增的跨V1簇合并

V4形成了多个由不同 V1 簇组成的新簇：

| V4簇题数 | 主要候选名称 | 对应的V1来源 |
| ---: | --- | --- |
| 279 | 听句子选图、句子与图片匹配题 | V1的258题簇 + 另一V1簇中的21题 |
| 261 | 听力匹配题、句子与图片匹配、听力图片匹配 | V1的216题簇 + 30题 + 15题 |
| 250 | 听力图片匹配题、听力选图题、听录音选图片 | V1主簇中的244题 + 3题 + 3题 |
| 56 | 听力配对题、听独白信息配对 | V1的55题簇 + 1题 |
| 32 | 听描述选图、图片听力匹配等 | 来自4个V1簇 |
| 12 | 听对话选图、听对话选择图片 | 来自2个V1簇 |
| 11 | 听力图片排序题、听力排序题 | V1的6题簇 + 5题簇 |

这说明机制主导确实能发现 V1 未覆盖的跨名称联系。尤其是排序题之间的合并、听对话选图之间的合并，以及多种听力选图表述之间的连接，都具有实际价值。

#### V4同时拆开了V1已有簇

听力匹配共有9个 V1 簇被 V4拆分。例如：

- V1的58题“句子与图片匹配”簇被拆为21、30、7题，并分别进入不同V4簇
- V1的262题“听力图片匹配”簇被拆为15、244、3题，并分别进入不同V4簇

因此，V4虽然形成了10个跨 V1 簇的合并簇，但拆分行为抵消了部分收益，最终簇数反而从46增加到49。

#### 当前仍未达到目标粒度

V4最大的三个簇仍为：

- 279题：听句子选图等
- 261题：听力匹配题等
- 250题：听力图片匹配题等

三者合计790题，核心任务都属于听力匹配，却仍保持为三个独立大簇。按照当前只保留“大题型”的要求，这说明跨名称归并仍未完成。

听力匹配的结论是：V4提供了重要的合并证据和更高覆盖率，但其完整分区不是最终答案。

## ⚙️ 最新版相对V1实际改进了什么

### 改进一：高置信度的部分信息题可以参与核心聚类

V1中听力和图片材料缺失的题目更容易进入辅助层或异常记录。最新版允许高置信度且 `information_sufficiency=partial` 的题目参与核心聚类，使听力匹配的异常题从11道下降到3道。

这一改进应当保留，因为题干即使没有附带实际音频，也可能已经足以判断“听句子选图”或“听力匹配”。

### 改进二：同一个标准化候选名称不会被拆分

最新版先按照标准化后的 `candidate_type_label` 建立名称组，并把名称组作为最小聚类单位。同一个名称组中的题目不会因为 `task_mechanism` 的措辞不同而被拆开。

该约束解决了逐题聚类对自然语言差异过度敏感的问题，应继续保留。

### 改进三：可以发现跨V1簇的机制联系

最新版将现有 `task_mechanism` 作为主要相似度依据，可以连接名称不同但机制相近的 V1 簇。语法填空的875题大簇，以及听力匹配的多个跨簇连接，证明这部分信息具有增量价值。

### 改进四：输出更适合后续分析

最新版增加了：

- `candidate_label_group_count`
- `stable / micro / unresolved`簇状态
- 组特征块归一化方式
- 核心、辅助和异常题统计

这些字段不会直接提高聚类准确率，但使局部簇质量和参数影响更容易检查。

## ⚠️ 最新版仍存在的核心问题

### 问题一：它重新生成分区，而不是在V1上只做合并

这是当前最重要的问题。最新版以候选名称组重新聚类全部题目，因此既可以合并 V1 簇，也可以拆开 V1 簇。

当前目标是减少 V1 中同义大题型的过度拆分。除非有明确证据证明 V1 簇内部混入了不同大题型，否则没有必要在局部阶段重新拆分 V1 已有簇。

### 问题二：自由文本机制仍不足以稳定决定所有边界

当前只使用字符级 TF-IDF。即使把机制权重提高到0.8，“听句子选图”和“听力图片匹配题”等表达仍可能因为表面字符差异而保持分离。

同时，同一 V1 簇中的不同候选名称组也可能因为机制描述详略不同而被分开。这解释了为什么听力匹配既出现新合并，又发生原簇拆分。

### 问题三：簇数增加掩盖了局部的有效合并

V4不是完全无效：它确实找到了有价值的连接。但由于拆分和合并同时发生，仅看最终49个簇无法判断这些连接是否值得采用。

需要把 V4从“最终分区生成器”改为“V1簇合并关系发现器”。

## 🔧 推荐解决方案：以V1为底座，只允许合并

### 基本原则

V1的每个局部簇作为不可拆分的原子节点。最新版不再直接输出一套替代分区，只负责判断哪些 V1 节点应当连接。

```mermaid
flowchart LR
    accTitle: V1 Based Merge Only Clustering
    accDescr: V1 clusters remain indivisible while the latest mechanism-based grouping contributes only merge links, producing a coarser local partition without splitting baseline clusters.

    v1_clusters([📥 读取V1局部簇]) --> atomic_nodes[🔒 固定为原子节点]
    latest_groups[🏷️ 生成机制名称组] --> merge_links[🔗 提取跨簇连接]
    atomic_nodes --> merge_graph[⚙️ 构建合并图]
    merge_links --> merge_graph
    merge_graph --> components[🧠 计算连通分量]
    components --> local_summary([📝 输出合并后局部簇])

    classDef baseline fill:#f3f4f6,stroke:#6b7280,stroke-width:2px,color:#1f2937
    classDef process fill:#dbeafe,stroke:#2563eb,stroke-width:2px,color:#1e3a5f
    classDef output fill:#dcfce7,stroke:#16a34a,stroke-width:2px,color:#14532d

    class v1_clusters,atomic_nodes baseline
    class latest_groups,merge_links,merge_graph,components process
    class local_summary output
```

### 具体处理步骤

1. 按照 V1 参数生成或读取 V1 局部簇
2. 将每个 V1 簇视为不可拆分节点
3. 使用最新版的名称组和机制相似度结果寻找跨 V1 簇连接
4. 同一个最新版簇包含多个 V1 簇时，在这些 V1 节点间建立合并边
5. 对合并图计算连通分量
6. 一个连通分量输出为一个新的局部簇
7. V1异常题使用最新版质量规则重新尝试归入已有簇；无法归入的继续保留为异常

该方案只使用已有输出，不增加 DS 调用，不新增结构化特征，也不引入新的复杂模型。

### 为什么该方案更符合当前目标

- V1已有合理簇不会被拆开
- 最新版发现的跨名称关系仍可用于合并
- 完形标签在没有新增合并证据时保持V1的9个簇
- 听力匹配可以通过多个跨簇连接逐步归并为更大的主类型
- 结果是V1分区的严格粗化，改进方向可解释且容易核查

### 合并图诊断结果

将当前 V1 簇关系和 V4簇关系做只读并集诊断，可得到：

| 旧标签 | V1簇数 | V4簇数 | 合并图连通分量 | 最大连通分量 |
| --- | ---: | ---: | ---: | ---: |
| 语法填空（动词） | 21 | 27 | 23 | 875题 |
| 完形：动词/动词短语 | 9 | 11 | 9 | 645题 |
| 听力匹配 | 46 | 49 | 38 | 812题 |

这里的连通分量数量包含 V4新增覆盖而 V1未聚类的题目，因此语法填空的23个分量不能直接与V1的21个簇作简单减法比较。最重要的诊断信号是：

- 语法填空的846题和29题主簇能够合并为875题
- 完形标签保持V1的主要分区，没有被进一步错误合并
- 听力匹配形成812题的主连通分量，符合当前“大题型只保留听力匹配”的粒度方向

上述数字是基于现有两版成员关系计算的方案诊断，不是当前程序已经生成的正式结果。

## ✅ 下一版验收标准

### 必须满足

- 新结果中的任何簇都只能是一个或多个完整 V1 簇的并集
- 不允许一个 V1 簇被分配到多个新簇
- `clustered_rows + outlier_rows = 1000`
- 每道题最多属于一个新簇
- 合并前后的 V1 簇来源可以追溯

### 语法填空

- 846题“语法填空”和29题“单句语法填空”应合并
- V1的22题单词拼写簇不能再被拆为17题和5题
- V1的首字母填空簇不能因机制措辞差异被拆开

### 完形标签

- V1的9个簇原则上保持不变
- 单项选择645题和完形填空323题继续分离
- 在没有跨簇合并证据时，不因参数变化产生更多簇

### 听力匹配

- V1的262题、258题、216题和58题主簇应通过现有跨簇连接归入同一主类型
- 排序题可以内部合并，但不能仅因包含图片而与匹配题错误连接
- 原有 V1 簇不再被拆成15、244、3或21、30、7等部分
- 异常题降低带来的新增覆盖必须保留

## 🤔 当前方案的风险与待验证点

只允许合并能够消除当前回退，但会引入“错误连接传递”风险：如果一个跨簇连接判断错误，连通分量可能把多个大簇连在一起。

因此，正式实现时需要保留简单的连接证据：

- 连接由哪个最新版簇产生
- 两侧分别对应多少题
- 两侧主要候选名称是什么
- 代表性 `task_mechanism` 是什么

当前不需要增加新的特征提取。先在三个标签上检查合并边是否合理；如果出现单个极小名称组错误连接两个大簇，再增加最小连接题数或相似度要求，而不是重新设计整套聚类系统。
